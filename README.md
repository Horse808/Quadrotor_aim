# 无人机引导灯辅助降落

## 1. 项目目标

本项目基于 LicheeRV Nano（SG2002）、GC4653 前视相机和 PX4 飞控，验证通过视觉识别绿色引导灯辅助无人机接近目标区域，并在目标附近进入受控降落流程。

当前功能范围：

1. 从相机图像中检测绿色引导灯，输出检测状态、图像中心偏差和目标特征尺寸。
2. 在经过标定和受控测试后，估计无人机与引导灯之间的相对位置；目标是到达引导灯正前方约 50 cm 的预定位置。
3. 到达并稳定在预定位置后，按独立验证过的降落流程下降；目标丢失、测距无效、通信异常或状态不确定时，不继续自动下降，并进入已定义的安全处理流程。

> “正前方 50 cm”指无人机与引导灯之间的水平/前向间隔，不是离地高度。实际坐标定义、允许误差、飞行高度和降落点几何关系，须结合安装方式和测试场地明确。引导灯本身不一定等于安全的着陆点。

本项目不包含撞击、冲刺或高速接触目标的功能。程序能识别目标或输出设定值，不代表已具备安全自主飞行能力；所有飞行验证须逐级进行，并保留人工接管能力。

## 2. 硬件与软件基线

以下配置来自 `PROJECT_HANDOFF.md` 的上一功能记录，是开发参考，部署前需在当前板端重新核实：

- 板卡：LicheeRV Nano（SG2002，RISC-V 64 位，Linux/musl）。
- 图像传感器：GC4653 MIPI，记录配置为 1280×720 @ 60 FPS。
- 图像链路：VI/ISP → VPSS 硬件缩放 → 当前配置通常为 640×360 → OpenCV。
- 飞控串口：板端 `/dev/ttyS1`，MAVLink 2，记录波特率 230400。
- 速度设定值：上一项目使用 `SET_POSITION_TARGET_LOCAL_NED`，默认发送频率 20 Hz；新功能接入前应核实实际代码、飞控配置和坐标方向。

传感器模式、相机标定、波特率、串口映射和目标架构运行库都可能随镜像、SDK 或板端配置变化。以源码、当前板端配置和实测结果为准，不要仅凭此处记录直接飞行。

## 3. 功能模块建议

### 3.1 相机采集

复用 Nano 原生 VI/ISP 与 VPSS 数据通路，明确输入和输出分辨率、灰度/彩色格式、stride 与帧缓存生命周期。若算法在缩放图像上运行，坐标和相机内参必须使用同一分辨率尺度。相机通常只能由一个进程占用。

### 3.2 引导灯检测

检测结果至少应包含：是否检测到、图像中心坐标、边界/面积或等效直径、置信度（若算法支持）及帧时间戳。不要仅以“最大亮斑”作为目标身份依据；应评估环境绿光、反光、饱和光斑和多个候选目标造成的误检，并通过连续帧一致性与合理的目标范围过滤偶发检测。

检测器应对空图像、错误图像类型、无候选目标及非法参数返回明确的无效结果，不得输出未初始化或非有限数值。

### 3.3 相对位置估计

单目相机仅凭光斑面积估距容易受曝光、阈值、光晕和灯具角度影响。若使用已知灯具尺寸估距，应先确认实际发光区域尺寸、相机内参、镜头畸变和图像缩放关系，并在多个已知距离、光照和姿态下记录误差。不得把未经验证的像素阈值直接视为 50 cm。

进入降落判定前，应明确距离数据的有效范围、更新时间、连续稳定帧数和容许误差；距离无效或过期时应禁止继续执行自动下降。

### 3.4 降落状态逻辑

建议将识别与控制分开，并显式定义状态及转移条件，例如：

- `SEARCH`：等待/搜索引导灯；
- `ACQUIRE`：确认目标连续可见且检测质量合格；
- `APPROACH`：在受限速度和范围内接近预定位置；
- `HOLD`：确认约 50 cm 的前向间隔及姿态/位置稳定；
- `DESCEND`：仅在高度、目标有效性、飞控状态和通信均满足条件时执行已验证的下降流程；
- `ABORT/FAILSAFE`：目标丢失、数据过期、超时、数值异常、相机或通信故障时停止继续下降，并按经验证的飞控保护策略处理。

状态转换应有超时、滞回和连续确认，避免单帧误检导致动作切换。程序退出、串口断开或模式切换本身不等于安全悬停或安全降落；须验证 PX4 的 Offboard 失联保护和人工接管流程。

### 3.5 飞控通信

复用现有 `Communicate` 层，避免重复打开 UART 或重复解析 MAVLink。保持既有 `FcState`、`FcCommand` 字段语义、单位、坐标约定和发送周期；若确需变更，必须同步更新所有调用端并逐轴验证方向。命令超时、心跳丢失、无效值及非有限数值都应有明确的零指令/故障处理，并验证零指令行为符合当前飞控模式的预期。

## 4. 验证路线

1. **工程与配置核对**：盘点从上一项目复制来的文件和依赖；核对当前相机、SDK、构建入口、配置默认值。先确保运动输出关闭。
2. **相机独立验证**：确认传感器初始化、VI→VPSS 输出分辨率、稳定帧率、超时和资源释放。
3. **离线识别验证**：使用保存图像/视频覆盖不同距离、背景、曝光和遮挡情况，统计误检、漏检、中心误差和处理耗时；先只显示/记录结果。
4. **距离标定**：用实测距离数据验证估距误差及 50 cm 判定的重复性；检查相机内参是否与处理分辨率匹配。
5. **拆桨台架验证**：确认 MAVLink 心跳、遥测新鲜度、零指令、命令超时、状态切换和人工停止路径；不以“收到设定值”代替飞控行为验证。
6. **受控飞行评估**：只有前述环节通过、飞控 failsafe 与遥控接管已验证后，才由有经验的操作者在空旷安全场地逐步评估。先低速、短时、可随时接管；每次只改变一个因素。

## 5. 验收指标（测试前填写）

- 引导灯实际特征尺寸及安装位置：待实测记录。
- 识别距离范围、误检/漏检率、目标丢失恢复时间：待测试定义。
- 目标中心误差及处理时延：待测试定义。
- 50 cm 位置的测距误差、重复性与允许范围：待标定定义。
- 进入降落前的目标连续有效时长、位置稳定条件和高度条件：待定义。
- 相机/飞控通信故障时的预期行为、人工接管方式及 PX4 failsafe：须在测试前验证。

在这些指标明确并完成验证前，程序应保持为视觉与状态验证工具，不应默认启用自主运动输出。

## 6. 引导灯识别实现

主程序 `main` 在构建时直接编译 `src/light_detector.cpp`，通过 `detectLight()` 获取绿色圆形引导灯的检测结果。识别阈值及相机参数读取 `config/camera_config.yaml`，飞行参数读取 `config/fly_config.yaml`。主程序要求 VPSS 成功输出 320×180 图像；若 VPSS 初始化失败会打印错误并退出，不再静默回退到 1280×720 的 CPU 转换/缩放，以免处理帧率骤降或使用错误图像尺度。退出时会分步禁用 VPSS 通道、停止并销毁 group，再释放 VB pool。

## 7. 引导灯识别实时预览测试

`aim_light_test` 是独立视觉测试程序，不连接飞控、不发送飞行指令。程序读取 `config/camera_config.yaml` 中的处理分辨率和绿色引导灯识别阈值，直接调用与主程序相同的 `src/light_detector.cpp`，在图像上叠加检测框、中心点、置信度和帧率，再以 MJPEG over TCP 传输。程序要求 VPSS 成功提供配置分辨率，VPSS 不可用时会退出，避免静默使用高负载 CPU 回退路径。

在项目目录交叉编译后，将 `build-nano/aim_light_test`、`build-nano/lib/` 和 `config/camera_config.yaml` 部署到小电脑同一项目目录。小电脑上运行：

```bash
LD_LIBRARY_PATH="$PWD/lib:$LD_LIBRARY_PATH" ./aim_light_test
```

程序默认监听 TCP 5000 端口。在笔记本电脑上运行以下命令查看（替换为小电脑 IP）：

```bash
ffplay -fflags nobuffer -flags low_delay -framedrop \
  -f mjpeg tcp://小电脑IP:5000
```

该预览使用有损 JPEG；画面帧率受 VPSS、检测、JPEG 编码和网络共同影响。退出时按 `Ctrl-C`，程序会关闭连接并释放相机与 VPSS 资源。请勿与主程序或其他相机测试程序同时运行。

### 相机曝光调整

`main` 和 `aim_light_test` 在相机 ISP 初始化、预热完成后，统一调用相机节点读取
`config/camera_config.yaml` 中的 `exposure_time_us`：

- `0`：自动曝光（默认值；旧配置缺少此项时也使用自动曝光）。
- 正整数：手动曝光时间，单位为微秒。例如 `2000` 表示 2 毫秒。
  手动模式固定模拟增益、数字增益和 ISP 数字增益为 1 倍，避免自动增益重新提亮灯芯。
- 参数不是整数、为负数、超过 ISP 传感器单帧时间，或 ISP 接口调用失败时，
  程序会报错、释放相机资源并退出；主程序不会继续连接飞控执行任务。

灯芯过曝时，先只运行 `aim_light_test`，可从 `2000` 微秒开始，逐步试 `1000`、`500`；
若画面过暗或绿色外圈消失则增大。数值是调试起点，并非当前灯具的标定结果。
GC4653 的 60 帧/秒模式下上限为 16666 微秒，即使 VPSS 输出帧率较低也不能据此放宽；
传感器可能按曝光行数对请求值取整。修改板端配置后重启程序即可，不需重新编译。

曝光设置不会修改白平衡或绿色识别算法。其它独立采集/标定及 ArUco 测试程序维持原行为，
未接入此配置。曝光调整也可能改变光晕和检测直径，正式使用前应在已知距离重新核验识别和估距结果。

## 8. 原始采集与软件 MJPEG 传输测试

`camera_compressed_stream_test` 是独立的相机传输测试程序：它不读取
`config/camera_config.yaml`，也不执行绿色识别、画框、滤波或飞控控制。当前测试程序直接读取相机
Y 平面并传输灰度图，不做 BGR 转换，以减少 CPU 负担。测试专用参数直接写在
`test/camera_compressed_stream.cpp` 的常量中；修改参数后必须重新交叉编译。当前默认值为：

```cpp
kOutputWidth  = 360;
kOutputHeight = 180;
kStreamPort   = 5001;
kStreamFps    = 30;
kJpegQuality  = 80;
```

`config/camera_config.yaml` 中的 `input_width` / `input_height` 仍属于主识别程序的处理分辨率，
测试程序会忽略它们。这样修改测试输出尺寸、端口、帧率或 JPEG 质量时，不会污染识别程序的配置。

当前测试路径不再依赖 Nano 的 VENC 硬件编码器，而是：

```text
VI/ISP → VPSS（可用时硬件缩放）→ Y 平面灰度图 → SDK 内置 stb 灰度 JPEG → TCP MJPEG
```

这样可以绕开板端 VENC 没有输出 JPEG 的问题，先验证“相机采集—灰度软件编码—网络—笔记本
ffplay”链路和实际发送帧率。灰度 JPEG 比彩色 JPEG 少一次 YUV→BGR 转换，通常能降低 CPU 占用和网络带宽；软件 JPEG 仍会占用 CPU；后续如果需要降低 CPU 占用，再单独恢复
硬件 VENC 测试，不让它阻塞当前功能验证。

重新构建后，部署以下内容：

- `build-nano/camera_compressed_stream_test`
- `build-nano/lib/`

测试程序不需要部署 `config/camera_config.yaml`；运行主程序 `main` 时需部署 `config/camera_config.yaml`。

小电脑上运行：

```bash
cd /root/aim_light
LD_LIBRARY_PATH="$PWD/lib:$LD_LIBRARY_PATH" \
  ./camera_compressed_stream_test
```

默认监听 TCP `5001` 端口。笔记本电脑上使用 `ffplay` 观看：

```bash
ffplay -fflags nobuffer -flags low_delay -framedrop \
  -f mjpeg -framerate 30 \
  tcp://小电脑IP:5001
```

注意：这个端口发送的是连续 JPEG 帧，必须使用 `-f mjpeg`，不能使用
`-f rawvideo -pixel_format bgr24`。`rawvideo` 会把 JPEG 压缩字节误当成 BGR 像素，因此画面会花屏。

`kOutputWidth` / `kOutputHeight` 使用 `360×180` 等偶数尺寸时会先尝试由 VPSS 硬件缩放；若日志出现
`VPSS output ... unavailable`，表示 VPSS 的缩放通道没有成功建立；相机采集测试程序仍会从 VI
读取 `1280×720`，再在 CPU 中缩放到代码中指定的输出尺寸，继续软件 JPEG 和 TCP 测试。随后日志会给出
`VPSS init request`、VB pool、`SAMPLE_COMM_VPSS_Start` 和 VI-to-VPSS bind 的具体返回结果，便于定位
板端的 VPSS 失败阶段。

`kStreamFps` 控制编码和发送节拍，`kJpegQuality` 控制软件 JPEG 质量。程序每 5 秒打印：采集帧率、
编码帧率、完整发送帧率、平均 JPEG 大小以及读取/编码/发送失败次数；其中 `sent` 才是已经完整写入
TCP 的帧率，更适合和笔记本端的显示效果对照。修改上述常量后，在开发机重新运行 `./build_nano.sh`
并重新部署测试程序即可。

客户端断开后，程序会释放连接并等待下一次连接；收到 `Ctrl-C` 后会停止 TCP、停止 VPSS、释放 VPSS
输出池、关闭 VI/ISP 和系统资源。测试程序不能与主程序 `main` 同时运行，因为两者都会占用 GC4653 相机。

如果笔记本仍然没有画面，先确认小电脑日志中出现 `[stream] laptop connected`，并确认笔记本可以访问
小电脑的 `5001` 端口。若 `encoded` 大于 0 但 `sent` 为 0，重点检查网络或客户端；若 `read_failures`
持续增加，重点检查相机占用、传感器配置和 VI/VPSS 初始化。

### 与飞控通信的注意事项

- 程序默认使用 `/dev/ttyS1`、230400 baud、8N1；板端必须确认 UART 设备、波特率、A28/A29 交叉接线和共地与飞控配置一致。一个串口只能由一个进程独占，先停止 `landing`、心跳监听器等占用同一 UART 的程序。
- 收到 PX4 心跳后，程序通过该 UART 发送 `MAV_CMD_SET_MESSAGE_INTERVAL`（command 511），请求 `OPTICAL_FLOW_RAD`（message ID 106）以 20 Hz 输出，并等待 `COMMAND_ACK`。只有收到接受确认后才继续预检；飞控端还需允许该命令、该串口 MAVLink 实例需正常收发。
- 光流消息请求是按当前 MAVLink 链路发出的，不等于永久修改飞控参数；重启程序后会再次请求。若请求被拒绝或超时，程序会停止，不会切模式或解锁。可在 PX4 NSH 用 `mavlink status` 确认对应 serial instance，并用 `listener vehicle_optical_flow` 检查飞控内部光流；本程序实际订阅的是 MAVLink `OPTICAL_FLOW_RAD.distance`，不是直接读取 UORB。
- **降落解除武装注意：** 正常飞行模式到达配置的 `landing_stop_height_m` 时，程序会发送 `MAV_CMD_COMPONENT_ARM_DISARM`，其中 `param1=0` 表示解除武装，`param2=21196` 是 PX4 的强制解除武装标记。该指令会绕过部分解除武装检查，可能在仍有离地高度时立即停止电机并导致坠落。阈值必须依据实测光流离地距离设置；先拆桨验证命令链路，再由遥控器接管人员在空旷场地、极低高度测试。测试模式不会发送解除武装命令。
- 进入动作前要求心跳与有效光流连续 5 秒。运行中若心跳、光流、Offboard 或解锁状态失效，程序停止发送非零运动设定并持续发零速度；零速度并不等同于位置/高度锁定，遥控器必须随时可接管。
- 可在 NSH 通过 `listener trajectory_setpoint 5` 核对垂直速度和 yaw 速度设定。MAVLink `SET_POSITION_TARGET_LOCAL_NED` 的 `yaw_rate` 单位为 rad/s；程序命令行则用度/秒。

### 引导灯飞行主程序

飞行主程序源文件为 `src/main.cpp`，构建产物为 `build-nano/main`。默认从 `config/` 目录读取
`fly_config.yaml` 和 `camera_config.yaml`。可使用 `--config-dir` 指定同时包含这两个文件的配置目录；
旧参数 `--config` 仍可单独指定飞行配置文件。运行前需部署 `main`、完整的 `lib/` 和两个配置文件，
并确保当前没有其他程序占用相机或 UART。例如：

```bash
./main --test --config-dir /mnt/data/Quadrotor_aim/config
./main --normal --config-dir /mnt/data/Quadrotor_aim/config
```

搜索阶段优先以飞控相对高度反馈稳高，只有该高度暂不可用时才回退到光流测距值。识别到引导灯后，状态机先用垂直速度将灯中心对齐图像中心高度，再通过偏航将灯对准画面水平中心，最后前后靠近。短暂丢失目标时会沿用最近一次目标估计继续跟踪，最长时间由 `fly_config.yaml` 的 `target_loss_hold_seconds` 控制（默认 1.5 秒，允许 0–10 秒）；超时后返回搜索。此“高度对齐”基于前向相机图像中心，若相机有俯仰安装角，需按实际安装调整目标位置/验证飞行表现。

默认 `--test` 模式只发送速度设定值，不切换 Offboard、不解锁，也不发送停桨命令；只有明确使用
`--normal` 才执行切换 Offboard、解锁，并在光流高度达到 `landing_stop_height_m` 时发送强制解除武装命令。建议先用测试模式核对识别方向与设定值，正常模式必须由具备遥控器接管能力的人员在空旷场地测试。

高度控制使用两个已有速度参数（均填写正值，单位米/秒）和一个可配置高度阈值：起飞发送 `-takeoff_speed_mps`；搜索高度进入 `search_height_m ± height_tolerance_m` 容差后，持续发送 `-vertical_speed_mps`；低于容差下限时发送 `-takeoff_speed_mps`，高于容差上限时发送 `+takeoff_speed_mps`。`height_tolerance_m` 只控制搜索阶段高度阈值，`vertical_tolerance_m` 仍只控制引导灯上下位置误差。高度修正与悬停速度互相覆盖，不叠加、不经过比例增益缩小；搜索高度修正不受 `vertical_speed_mps` 限制。跟踪时无需垂直对齐的转向、靠近和到位等待阶段也发送 `-vertical_speed_mps`，主动视觉垂直对齐仍沿用原增益和速度上限。旧的 降落、停桨及失效保护逻辑不变。这是持续的向上速度指令，并非真正的锁高或推力补偿，可能导致高度来回调整，设置过大可能持续爬升，需受控验证。

注意：强制解除武装会绕过飞控部分检查，阈值过高可能造成空中停桨和坠落。必须根据实测离地距离校准 `landing_stop_height_m`，先拆桨验证通信，再在极低高度受控测试。测试模式不会执行停桨。搜索超时后状态机按既有逻辑转入降落；若任务场景不允许盲目降落，应先调整状态机策略。

### 相机标定参数

`config/camera_config.yaml` 中的 `camera_matrix` 保存 GC4653 在原始标定分辨率 `1280x720` 下的内参，`calibration_image_width` / `calibration_image_height` 明确记录该矩阵对应的分辨率。引导灯主程序及 ArUco 测试程序共用内参缩放函数，按实际算法图像尺寸自动缩放焦距和主点；当前两者均处理 `320x180` 图像，缩放比例为 0.25。`input_width` / `input_height` 是处理尺寸，不是内参的参考尺寸；修改处理尺寸时不要手动改写原始内参。畸变系数保持标定原值。程序与此配置文件必须一起更新，避免新旧缩放规则混用。

注意：引导灯主程序已读取缩放后的内参，用于灯直径测距和目标位置换算，但尚未在引导灯图像链路中执行畸变校正；ArUco 测试程序会把缩放内参及畸变系数传给位姿解算。改变这些数据不会自动改变预览画面。
